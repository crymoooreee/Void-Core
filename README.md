# VoidCore
​
**VoidCore** — desktop-приложение для мониторинга производительности игр. Оно отслеживает FPS и время кадра, обнаруживает просадки и помогает определить их **вероятную причину** по доступным показателям оборудования и фоновых процессов.
​

<img width="1280" height="640" alt="VoidCore-social-preview" src="https://github.com/user-attachments/assets/f425b99c-fe5b-45d7-9dd6-96ebfc548e57" />

Проект ориентирован на игроков и разработчиков, которым важно не просто увидеть низкий FPS, а получить данные для диагностики проблемы.

> **VoidCore находится в разработке.** README описывает возможности, подготовленные для релиза **0.4.9**, включая 1% Low / 0.1% Low, постоянную историю сессий, обратимый игровой профиль и обновления через GitHub Releases. Проверки логики в тестах не заменяют проверку захвата кадров и влияния программы на производительность на Windows.
​
## 🎮 Основная идея
​
Обычные FPS-счётчики показывают результат:
​
> FPS упал со 120 до 45.
​
VoidCore помогает ответить на следующий вопрос:
​
> **Почему FPS мог упасть?**
​
Во время игры приложение собирает телеметрию и сопоставляет падения FPS с последними доступными показателями системы.
​
```text
FPS DROP DETECTED
120 FPS → 48 FPS
​
GPU Load:        98%
GPU Temperature: 82°C
CPU Load:        54%
RAM Usage:       71%
VRAM Usage:      96%
​
Вероятная причина:
Высокое использование VRAM
```
​
Высокая загрузка или температура — это диагностические признаки, а не доказательство причины. Например, высокая загрузка GPU сама по себе может быть нормальной для игры.
​
## 🔍 Что отслеживает VoidCore
​
В зависимости от оборудования, драйвера и доступности датчиков приложение получает:
​
- FPS;
- Frame Time — время кадра в миллисекундах;
- загрузку и температуру CPU;
- загрузку и температуру GPU;
- использование и общий объём RAM;
- использование и общий объём VRAM;
- информацию о распознанном процессе игры;
- загрузку CPU и использование RAM фоновых процессов;
- базовые характеристики CPU, GPU, памяти и операционной системы.
​
**GPU Power, частоты CPU/GPU и длительность фриза в текущей версии не отслеживаются.** Недоступные показатели отображаются как отсутствующие данные.
​
### Частота обновления
​
| Данные | Частота / условие |
| --- | --- |
| Захват кадров через PresentMon | Потоковый, пока работает монитор |
| Запрос текущего FPS интерфейсом | Раз в 250 мс на активном экране Overview, когда окно в фокусе |
| Сбор телеметрии и проверка просадок | Примерно раз в 2 секунды |
| Общий снимок оборудования и процессов | Кэшируется на 5 секунд |
| Запрос температуры CPU | Не чаще раза в 15 секунд |
| Характеристики компьютера | Кэшируются после успешного получения |
| Снимок телеметрии в истории сессии | Примерно раз в 10 секунд |
| Запись текущей сессии на диск | Примерно раз в 30 секунд; границы сессии — сразу |
| Расчёт 1% Low / 0.1% Low | Не чаще раза в секунду |
| Проверка питания при изменённом плане | Примерно раз в 15 секунд |
​
Это целевые интервалы, а не гарантированная точность: системные запросы могут занимать дополнительное время. Для анализа используются последние доступные значения, поэтому кратковременные изменения между замерами могут быть пропущены.
​
## 📉 Обнаружение просадок FPS
​
VoidCore сравнивает текущий FPS с базовым уровнем, рассчитанным по медиане последних доступных положительных значений FPS.
​
Текущая реализация:
​
- использует до 12 предыдущих положительных замеров FPS;
- требует минимум 5 подходящих замеров для формирования базового уровня;
- обнаруживает падение примерно на **28% и не менее чем на 12 FPS** относительно базового уровня;
- подтверждает умеренную просадку следующим замером;
- может создать событие сразу при падении на **50% и более**;
- ограничивает частоту диагностических событий: не чаще одного раза в 8 секунд.
​
```text
FPS DROP
──────────────
Time:       21:43:17
FPS:        144 → 62
Frame Time: 16.1 ms
​
Вероятная причина:
Высокая загрузка GPU
```
​
Frame Time отображается и сохраняется в событии как дополнительная метрика. **Отдельный детектор скачков Frame Time и измерение длительности просадки пока не реализованы.** Короткие фризы между проверками могут не создать событие.
​
### Фильтрация ложных срабатываний
​
При подозрении на просадку приложение проверяет доступное состояние захвата кадров и окна игры. Событие может быть отфильтровано, если:
​
- игра свёрнута;
- игра не находится на переднем плане;
- игровое окно скрыто;
- нет свежих кадров или захват остановлен.
​
Отфильтрованные события хранятся отдельно. На странице Diagnostic отображаются их количество в текущей истории и причина последнего события.
​
Проверка состояния окна работает на Windows и является приблизительной. Короткие переключения между проверками могут быть пропущены; при недоступности проверки состояния окна фильтр по фокусу не применяется.
​
**System Idle Process исключён из анализа фоновой нагрузки:** его высокий процент показывает свободное процессорное время, а не нагрузку на CPU.
​
## 🧠 Анализ вероятной причины
​
VoidCore использует базовые правила и пороги для классификации событий. Среди возможных категорий:
​
| Категория | Пример диагностического признака |
| --- | --- |
| Возможное ограничение CPU | Высокая общая загрузка CPU при меньшей загрузке GPU |
| Возможное ограничение GPU | Очень высокая загрузка GPU |
| Высокое использование VRAM | Использование VRAM около 90% и выше |
| Высокое использование RAM | Использование RAM около 90% и выше |
| Возможный перегрев | Температура CPU около 90°C или GPU около 85°C и выше |
| Возможное влияние фонового процесса | Значительная загрузка CPU или использование памяти другим процессом |
| Неопределённая кратковременная задержка | Не обнаружены критические значения отслеживаемых показателей |
​
Температурные пороги являются эвристикой, а не универсальными пределами для всех моделей оборудования. Без измерения частот и признаков троттлинга нельзя подтвердить, что перегрев вызвал падение FPS.
​
Общая загрузка CPU также не исключает ограничения отдельного ядра при умеренной суммарной загрузке.
​
Пример:
​
```text
GPU: 61%
CPU: 96%
​
Результат:
Возможное ограничение со стороны CPU
```
​
Для неопределённой задержки приложение может предложить проверить компиляцию шейдеров, загрузку ресурсов или состояние игры, но **не обнаруживает эти причины напрямую**.
​
Результат всегда является **вероятной причиной, а не гарантированным диагнозом**.
​
## 💡 Рекомендации
​
В зависимости от категории события VoidCore предлагает действия для проверки и устранения проблемы, например:
​
- снизить качество текстур при высоком использовании VRAM;
- закрыть ненужные приложения при нехватке RAM;
- проверить охлаждение при высокой температуре;
- уменьшить графическую нагрузку при возможном ограничении GPU;
- проверить ресурсоёмкие фоновые процессы.
​
Приложение не завершает процессы автоматически. Не завершайте системные процессы Windows без понимания их назначения.
​
## ⚙️ Игровой профиль оптимизации
​
**Optimize PC больше не является заглушкой.** На Windows приложение может применять выбранные обратимые изменения. Профиль настраивается на странице **Optimizer**.
​
### Доступные действия
​
| Опция | Действие | Ограничение |
| --- | --- | --- |
| Приоритет игры | Above Normal для подтверждённого игрового процесса | Не используются High и Realtime; возможен отказ ОС или античита |
| Приоритет VoidCore | Below Normal для процесса приложения | Может увеличить задержку интерфейса и обработки телеметрии |
| Высокая производительность | Включение уже существующей стандартной схемы питания High Performance | Только при подтверждённом питании от сети или отсутствии батареи; если схема отсутствует, действие пропускается |
| Запись Xbox Game DVR | Отключение двух пользовательских параметров записи на время профиля | Запись/клипы могут стать недоступны; эффект может требовать перезапуска игры |
​
Новые системные опции **выключены по умолчанию** и включаются отдельно с предупреждением. Приоритеты применяются только вместе с подтверждённым ручным профилем или явно включённым автоматическим режимом.
​
### Применение
​
1. Откройте **Optimizer** и выберите нужные действия.
2. Запустите поддерживаемую игру.
3. Нажмите **«Применить к текущей игре»** или **Optimize PC** и подтвердите действие.
4. Для последующих сессий при необходимости включите **автоматический профиль**. Эта настройка сохраняется между запусками.
5. Чтобы отменить изменения и выключить автоматический режим, нажмите **«Восстановить»**.
​
Само изменение опций сохраняет настройки и отменяет предыдущий профиль; новое применение выполняется отдельно или при обнаружении игры в автоматическом режиме.
​
### Восстановление и защита
​
- Исходные значения записываются в локальные журналы **до изменения**.
- Применение и восстановление системных настроек проверяются повторным чтением.
- Откат выполняется при завершении/смене игры, нормальном выходе из VoidCore или нажатии «Восстановить».
- После аварийного завершения восстановление предпринимается при следующем запуске.
- Приоритет игры восстанавливается только при совпадении PID, названия и времени запуска процесса. При отсутствии времени запуска его изменение пропускается.
- Если текущие значения отличаются от применённых профилем, они не перезаписываются при откате — это защищает изменения пользователя или другой программы.
- Если параметр Game DVR изначально отсутствовал, откат удаляет только созданное значение, а не весь ключ реестра.
- При обнаружении перехода на батарею или неизвестного источника питания собственное изменение схемы питания отменяется. Проверка выполняется периодически, не мгновенно.
- Частичная ошибка не считается полным успехом; данные для повторного отката остаются в журнале.
- Повреждённый журнал блокирует соответствующий профиль и сохраняется без автоматической перезаписи.
​
Журналы находятся в папке данных приложения: `optimizer.json` и `system-profile.json`. Восстановление может не завершиться при ошибке доступа — в этом случае журнал сохраняется для повторной попытки.
​
### Безопасность и реальный эффект
​
**Прирост FPS не гарантируется.** Профиль может помочь, если потери связаны с энергосбережением, конкуренцией за CPU или записью, но не увеличивает мощность оборудования и не устраняет перегрев или нехватку VRAM.
​
High Performance может увеличить нагрев, расход энергии и шум. При температурном ограничении FPS способен ухудшиться. Изменения Game DVR не гарантируют остановки уже запущенной записи. Если они требуют перезапуска игры, после завершения профиля настройки могут уже восстановиться.
​
Антивирус и службы не отключаются. Фоновые приложения не завершаются. Не изменяются напряжения, частоты оборудования, файл подкачки, BCD и таймеры Windows. Не выполняется принудительная «очистка RAM». Автоматическое повышение прав не применяется.
​
Сравнивайте несколько повторов одной сцены с одинаковыми настройками, после прогрева, с профилем и без него. Оставляйте только действия, которые действительно помогают на вашем ПК.
​
## 📊 Постоянная история игровых сессий
​
На странице **Sessions** доступны сохранённые сессии и их подробности. История остаётся доступной после перезапуска приложения.
​
### Начало и завершение
​
- Сессия начинается при обнаружении поддерживаемого процесса игры.
- Сессия завершается при закрытии игры, смене выбранного игрового процесса или полном выходе из VoidCore.
- Крестик окна скрывает приложение в трей: мониторинг и текущая сессия продолжаются.
- После повторного запуска VoidCore создаётся новая сессия, даже если игра оставалась открытой.
- Время, когда VoidCore не работал, не добавляется к сохранённой сессии.
​
Обнаружение начала и завершения может задерживаться на несколько секунд из-за периодического опроса процессов. Длительность отражает время мониторинга найденного процесса: меню, загрузка и фоновый режим могут входить в неё.
​
### Сохраняемые данные
​
- Название, платформа и PID игры.
- Дата и время начала, завершения, длительность и статус.
- Версия VoidCore и доступные характеристики компьютера.
- Число валидных замеров FPS, средний, минимальный и максимальный FPS по замерам.
- Средний Frame Time по доступным валидным измерениям.
- Диагностические события, вероятные причины и рекомендации.
- Отфильтрованные срабатывания.
- Разреженные снимки телеметрии.
​
**Средний FPS рассчитывается по периодическим замерам, а не по всем кадрам.** Это не полноценный benchmark. Свежие положительные значения FPS из фонового режима могут входить в статистику; нулевые и устаревшие значения FPS либо остановленный захват исключаются из среднего FPS.
​
### Сохранение и восстановление
​
Начало и завершение сохраняются сразу. Текущая сессия записывается пакетно примерно раз в **30 секунд**, а снимки телеметрии добавляются примерно раз в **10 секунд**. При нормальном выходе приложение ожидает сохранения истории.
​
При аварийном завершении последняя сохранённая активная сессия получает статус **«Прервана»**, а её конец фиксируется по последнему сохранённому замеру. Последние несохранённые данные могут потеряться — обычно до 30 секунд при штатной работе записи; при зависании или ошибке диска этот интервал может быть больше.
​
Одна сессия хранит последние **7200 снимков** и **500 событий**, но суммарные счётчики и статистика охватывают все обработанные замеры сессии. Завершённые сессии автоматически не удаляются. Список отображается с пагинацией по 20 записей.
​
Повреждённые записи не перезаписываются автоматически; доступные записи можно продолжать просматривать. Ошибки чтения и записи показываются на странице Sessions.
​
### Хранение и приватность
​
Файлы находятся в `app.getPath("userData")/sessions`, по одному JSON-файлу на сессию. На Windows стандартный путь обычно выглядит так:
​
```text
%APPDATA%/voidcore/sessions
```
​
Один экземпляр приложения обслуживает историю: добавлена защита от одновременного запуска нескольких экземпляров VoidCore.
​
### Краткая история текущего мониторинга
​
Отдельно от постоянных сессий в памяти хранятся последние 60 замеров для графика, до 50 диагностических событий и до 30 отфильтрованных событий. Телеметрия и диагностика сбрасываются при смене выбранного игрового процесса, чтобы не смешивать данные разных игр.
​
## 📈 1% Low / 0.1% Low
​
На **Overview** отображаются две карточки для оценки редких медленных кадров.
​
Для каждой метрики берётся среднее время самых медленных 1% или 0.1% кадров, затем результат переводится в FPS:
​
```text
Low FPS = 1000 / среднее время выбранных медленных кадров в мс
```
​
Это **не минимальный FPS и не FPS-перцентиль**.
​
- Окно расчёта — последние **12 000 валидных кадров**. Его длительность зависит от FPS.
- Обе метрики вычисляются с одной общей сортировкой не чаще раза в секунду.
- Для 1% Low требуется минимум **1000 кадров**, для 0.1% Low — **10 000 кадров**, чтобы в медленном хвосте было хотя бы 10 кадров.
- До прогрева отображается **«Недостаточно данных»**, без свежих кадров — ожидание.
- Значения сохраняются в разреженных снимках сессий.
​
**Это скользящее окно, а не статистика всей сессии.** Итоговые покадровые 1%/0.1% Low всей сессии пока не вычисляются. Фоновые лимиты FPS могут влиять на результат; фильтрация диагностических уведомлений не исключает все такие кадры из расчёта Low. Кадры длиннее текущего фильтра 1000 мс не учитываются, поэтому очень длительные зависания могут быть исключены.
​

Наличие игры в списке означает наличие правила распознавания, а не подтверждённую совместимость захвата кадров со всеми её версиями и режимами.
​
Распознавание по имени процесса имеет ограничения. Например, `javaw.exe` не обязательно относится к Minecraft, а процесс лаунчера не всегда является процессом, который выводит игровые кадры. При нескольких одновременно запущенных играх выбор процесса требует дальнейшей доработки и не гарантирует выбор игры на переднем плане.
​
Метка Steam у игры является описанием платформы. **Интеграция с библиотекой Steam пока не реализована.**
​
После закрытия игры мониторинг останавливается при следующем обнаружении её отсутствия. Завершённая сессия сохраняется в постоянную локальную историю.
​

## 🛠️ Технологии
​
- **Electron** — desktop-оболочка;
- **electron-builder / NSIS** — сборка Windows-установщика;
- **electron-updater** — обновления через GitHub Releases;
- **JavaScript / Node.js** — логика приложения и системные запросы;
- **HTML / CSS** — интерфейс;
- **PresentMon** — получение телеметрии кадров на Windows через ETW;
- **systeminformation** — информация об оборудовании и процессах;
- **nvidia-smi** — получение доступных показателей NVIDIA GPU;
- **PowerShell / Win32** — проверка состояния окна игры и работа с фиксированными пользовательскими параметрами Game DVR;
- **powercfg** — переключение и восстановление доступной схемы питания Windows.

## 🏷️ Версия приложения
​
Единственный редактируемый источник номера версии — поле `version` в `package.json`. Номер автоматически отображается в боковой панели, Settings, заголовке окна и подсказке трея. Сборка использует тот же номер.
​
```bash
npm run version:patch
npm run version:minor
npm run version:major
npm run version:check
```
​
Для задания конкретного номера:
​
```bash
npm version 0.4.9 --no-git-tag-version
```
​
Номер версии управляется отдельно от обновлений. Изменение `package.json` не обновляет уже установленный EXE: нужен новый установщик.

## 🚀 Запуск и сборка
​
Основная целевая платформа для мониторинга FPS — **Windows**. Для разработки нужны Node.js и npm.
​
```bash
git clone https://github.com/crymoooreee/Void-Core.git
cd Void-Core
npm install
npm start
```
​
Для локальной копии проекта из архива достаточно выполнить `npm install` и `npm start` в её папке.
​
> README описывает набор возможностей для релиза 0.4.9. Фактический номер исходников проверяйте через `npm run version:check`. До публикации изменений клонированный репозиторий может отличаться от предоставленных исходников.
​
Перед запуском проверьте наличие файла:
​
```text
tools/presentmon/PresentMon.exe
```
​
Перед первой сборкой с поддержкой обновлений установите компонент:
​
```bash
npm run setup:updates
npm run version:check
npm run build
```
​
`setup:updates` устанавливает `electron-updater` как production dependency и синхронизирует package-файлы. До установки компонента обновления отключены, а проверка перед сборкой выдаёт инструкцию. После настройки зафиксируйте `package.json` и `package-lock.json`; для последующих установок зависимостей можно использовать `npm ci`.
​
Проверка версии и наличия компонента обновлений выполняется перед сборкой автоматически.
​
Настройка сборки предусматривает копирование PresentMon в ресурсы приложения. Создание и работу установщика необходимо отдельно проверять на Windows.

## ⚠️ Ограничения и влияние на производительность
​
- Работа захвата FPS через PresentMon/ETW требует Windows.
- Доступность температур, загрузки GPU и VRAM зависит от оборудования, драйверов и системных разрешений.
- Некоторые конфигурации могут требовать запуска от имени администратора. Повышайте права только при необходимости и доверии к используемым компонентам.
- Распознавание игр и фильтрация по состоянию окна не являются безошибочными.
- Фоновые снимки оборудования и процессов могут быть старше самого события просадки.
- Мониторинг имеет собственные накладные расходы; отсутствие влияния на FPS не гарантируется.
​
В текущей реализации снижена частота тяжёлых запросов, используется общий кэш процессов и оборудования, а обновления интерфейса и графика при неактивном окне приостанавливаются. Фоновый сбор FPS и диагностика продолжаются.
​
Чтобы оценить влияние программы, сравните одну и ту же сцену игры в одинаковых условиях:
​
1. Без запущенного VoidCore.
2. С открытым VoidCore.
3. С VoidCore, свёрнутым или не находящимся в фокусе.
​
Проводите несколько измерений после прогрева игры. Отдельно учитывайте загрузку ресурсов и компиляцию шейдеров. Сравнивайте не только средний FPS, но и время кадра и редкие задержки.
​
## 🧪 Проверки
​
```bash
npm run version:check
npm run test:version
npm run test:updates
npm run test:sessions
npm run test:low-optimizer
npm run test:system-optimizer
node tests/performance-v5.test.js
```
​
Тестами покрываются согласованность версии, отображение номера, сравнение стабильных версий, обработка ошибок обновлений, согласие пользователя и блокировка действий при обнаруженной игре. Для истории проверяются сохранение между перезапусками, смена игрового процесса, дедупликация событий, восстановление после аварийного выхода, повреждённые записи и ошибки записи.
​
Логика обновлений и операций оптимизации тестировалась с имитацией сервера/библиотеки и состояния ОС. Расчёты Low проверялись на синтетических данных; интерфейс истории и оптимизации — с тестовыми данными в браузере. Реальное обновление установленного приложения, завершение Electron на Windows, захват кадров и влияние на производительность требуют отдельной проверки на Windows.
